# Brainstorm / elicitation — topics with no source map

Read this when [`writing.md`](writing.md) sends you here: the topic has no source-navigation map yet,
so the shape has to be drawn with the author before writing. Run it as a conversation, then build the
map and return to `writing.md`.

Many authors think by brain-dumping and lean on the agent to condense — so **the agent produces the
tight artifacts (claim, order); it never demands them cold.** Ask until you reach shared
understanding; the author gives the vision.

- **Phase 0 — Dump (stance: expansive).** Invite them to talk it all out, unstructured. No crisp
  answers demanded. Only expansive moves: "say more," "what's the tension there," "where does that
  connect." Help them think. If the concept isn't solid yet, this phase runs longer.
- **Phase 1 — Mirror (stance: propose-and-confirm).** Once there's material, reflect the shape back
  as drafts they react to: "here's the through-line I'm hearing," "here's the order it wants to go,"
  "here's a candidate claim." The one-sentence claim is an *output the agent drafts for approval*,
  never an input they supply.
- **Phase 2 — Sharpen (stance: solidify).** Only after the shape is confirmed: scope seams, the
  ceiling for this concept, which parts need external rigor.

**Two can't-miss items** (forgetting either causes the classic failures):
1. **Surface what they've already made and the bridges they already use** — leverage them, don't
   reinvent. Authors have usually done a lot of conceptual bridging already; find and use it.
2. **Scope seams — what's explicitly deferred to sibling docs** — miss this and you get dropped
   threads or duplication.

When a topic already has a map, you skip this file: the map answers "what exists," and much of the
claim, scope, order, and misconceptions. Interview only the gaps.
