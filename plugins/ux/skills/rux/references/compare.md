# RUX Compare - competitor UX SWOT

Compare the user's page against named competitors through a UX lens, and return a SWOT that helps them stand out. Read `references/voice.md` for phrasing.

## Before you compare

1. Get the user's page and one to three competitor URLs or names. More than three dilutes the read; pick the closest rivals.
2. Confirm audience and goal, so "better" means better for this audience toward this goal, not in the abstract.
3. Inspect each site the same way you would for `evaluate`. Score lightly against the RUX categories in your head; the categories are the comparison axes.

## Procedure

Run each competitor through the same RUX lens, then compare on the axes that matter for this audience and goal. Common axes: clarity of purpose, trust signals, ease of the core task, content value, visual craft, accessibility.

Then write the SWOT from the user's point of view:

- **Strengths:** where the user's page already beats the field.
- **Weaknesses:** where competitors do better, with the specific thing they do.
- **Opportunities:** open ground nobody is covering well, that the user can take.
- **Threats:** where a competitor's advantage could pull the audience away.

Every point names the concrete UX detail behind it, not a vague impression. "Competitor B earns trust faster with named client logos above the fold" beats "Competitor B feels more trustworthy."

## Output

```
# UX comparison - [user's page] vs [competitors]
Audience: [x] · Goal: [x]

## How each stacks up
[user's page and each competitor, a few lines each on their UX read]

## SWOT for [user's page]
**Strengths**
- [point - concrete detail]
**Weaknesses**
- [point - concrete detail - which competitor does it better]
**Opportunities**
- [open ground the user can take]
**Threats**
- [where a rival could win the audience]

## Where to pull ahead
- [the two or three highest-leverage moves, ordered]

[compare disclaimer from voice.md]
[optional CTA {{researcher_offer}} from voice.md - omit entirely if unset]
```

In friendly register, keep it plain and close with the optional CTA from `voice.md` when one is set. In pro register, keep it as a competitive research read with no pitch.

## Honesty guardrail

This reads public surfaces against best practice. It cannot see the competitors' analytics, testing, or conversion. Frame advantages as visible UX advantages, and say that how the audience actually weighs these sites is a question for real research.
