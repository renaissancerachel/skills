# config-bootstrap — draft a missing manifest from the project's own evidence

Give a project the config/manifest it lacks, built from what the project actually is. This skill
owns the audit's missing-config finding. **Drafting is safe** (it writes only a proposal to a
scratch location); **creating the file in the live tree is `human-gated`** (the `human-gated`
track: a file move, rename, deletion, creation, or version-control operation a skill may only
propose while a human executes; the full finding taxonomy is defined once in the `workspace-audit`
skill's `references/findings.md`) — the skill drafts and stops.

## Step 1 — Confirm the gap is real

Verify the project is actively used yet has no config/manifest, so tooling silently falls back to
generic defaults. Confirm the specific file is genuinely absent (not merely elsewhere), and
identify which tool reads it and what defaults it uses when it is missing. If the project is early
enough that there is legitimately nothing to configure yet, say so and stop — an empty project is
not a finding.

## Step 2 — Gather the project's real identity from its own evidence

Scoped reads only, inside the target folder. Learn the schema from the tool that consumes the
config (and from a peer project's manifest of the same shape, if one exists). Then read the
project's own evidence — its scripts/renderers, source files, and existing settings — and extract
the values that describe what this project actually is. Cite the source of every value (the file,
and the line or setting it came from) so a human can verify without re-deriving.

## Step 3 — Draft the manifest

Write a `<name>.proposed` draft to a scratch/review location the user names — never into the live
tree. The draft:

- captures the project's real identity as read from its own evidence, one cited source per value;
- captures the project's **current effective behavior** as the baseline: spell out each setting
  exactly as the tool resolves it today, so encoding it changes nothing on its own;
- when a value intentionally **departs** from current behavior — a decision the manifest is meant to
  enact, not merely record — separate it from the behavior-neutral values and **headline the
  change**: name the old effective value, the new one, and why, so the human creating the file sees
  exactly what will behave differently and gates it deliberately;
- marks every value the evidence does not settle as an explicit **TODO / open decision** and says
  so — never invent a value to fill a gap;
- carries a one-line provenance stamp, e.g. `Generated by workspace-cleanup <date> — verify before
  use.`, with `<date>` taken from the harness at run time, never from a file's mtime;
- **references source paths rather than pasting full file bodies**, and **redacts any secret or
  credential** encountered while reading the project's evidence (note that it exists and where,
  never its value).

## Step 4 — Present and stop

Show the draft, the per-field provenance, and the list of open decisions. STOP here. Creating the
file in the live tree is human-gated: a human resolves the open decisions and creates it. At
create time, re-check the resolution base — confirm against the live code where the tool actually
reads the config from and what path it resolves relative to — immediately before the file is
created, because a cloud-synced read taken earlier may be stale.

## Safety specific to this skill

Beyond the family boundaries (stated centrally in the plugin's top-level `README.md`): **creating the config in the live
tree is human-gated** — this skill only ever writes a `.proposed` draft to scratch and presents it.
**Never fabricate a value**; missing evidence becomes a marked TODO, not a guess. **Re-check the
config's resolution base against the live code at create time** (stale-read rule).

## Done when

The missing-config gap was confirmed real (or the project was reported as too early to configure);
the project's real identity was extracted from its own evidence with a cited source per value;
a `.proposed` draft was written to scratch that encodes current effective behavior, headlines any
intentional departure from it (old value → new value, and why), and marks every unsettled value as
an open decision; the draft and its open decisions were presented; and nothing
was created in the live tree — that step, with its create-time resolution-base re-check, is left
to a human.
